# Keeping track of work

## In short

An agent forgets everything between sessions. Whatever must survive goes in writing, in one place, and is kept up to date.

## Use this when

- The work will take more than one session, or more than one person.
- You are about to stop with something unfinished.
- You made a choice the owner did not make, or the owner made one.
- Two notes about the same work say different things.

## Do this

1. **Keep one status note for each piece of work.** Put where things stand at the top and the history at the bottom. Start from `status-note-template.md`.
2. **Change the note; do not add another.** When something moves, rewrite the line that is now wrong. A second note is a second version of the truth.
3. **Date every status line** with the day it was last checked against the real system.
4. **Record every decision.** Write what was decided, who decided it (the owner or the agent), why, and until when it is still cheap to change. Start from `decision-record-template.md`.
5. **Write down what was postponed**, and the event that brings it back.
6. **List the questions only the owner can answer.** Give your recommendation for each, and carry on with everything that does not depend on the answer.
7. **Inside a product, save costly results as soon as you have them**, and make every step safe to run twice.
8. **When two actions can change the same record, make them take turns.** A late result from an older run must never replace newer information.

## Warning signs

- A new summary file sitting beside an older one.
- "I assumed" in a report, with no decision recorded.
- A status that can only be found by reading the history.
- Something postponed with nothing to bring it back.

## Why it matters

When the record is split across several notes, each reader acts on the one they found first. When a decision is not written down, the owner discovers it later as behaviour nobody remembers choosing.
